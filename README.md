# OOF Tracker

> "Education is the passport to the future, for tomorrow belongs to those who prepare for it today." - *Malcolm X*

## 📋 Description:
### <center>**📚 Γειά σου! 💙**</center>
This project is made for the primary purpose of logging and reviewing mistakes so you don't have to endure the hell of experiencing it again. Instead of looking at errors at just surface value, you can delve into what went wrong, why it happened and how you can mend the issue yourself.  

## 💡 Why / Motivation:
- To enjoy the progress of having fun with programming.
- To minimize frustration in academics (both in myself and you, too.)
- To recognize the current holes, gaps and actively workin' on fixing them.

## 🧠 Philosophy:
To put simply, this project believes that mistakes should **NOT** be considered as failures, but rather useful data to exploit.

Most of us have a tendency to encounter an error, then either ruminate it, or straight-up ignore it. While it seems effective short-term, this doesn't directly address the gaps that often resurface later in the long run.

Essentially, we believe in this mindset frequently:
> See problem → Attempt to solve it → Move on.

While seemingly efficient, it actually lets go an *essential* part about proper learning comprehension: **understanding the "why?" of a problem (an oof)**

This program, instead, deliberately creates a powerful mindset (or loop) to utilize:
> See problem → Fail → Analyze → Understand → Reinforce
## ✨ Features:
- **📝 Mistake Logging via commands:** Displays the logged problems with little to no clunk.
- **🗂 Categorization & Tagging:** Allows for easier tracking and filtering.
- ✏️ **Refinement & Iteration:** Modify existing entries to reflect deeper understanding, corrected reasoning, or improved explanations.
- **🔁 Quick Review Commands:** Retrieve and revisit past mistakes directly from the CLI.
- **📂 Structured Storage:** Mistakes are stored in a consistent format (e.g., JSON or text), making them easy to read and manage.
- **⚡ Lightweight & simple:** Makes logging mistakes not a constant hassle.
## 🛠️ How It Functions:
Here are the full details of a regular entry:
```
date: YYYY-MM-DD
subject: Math / Programming / Language / etc.
topic: Specific concept
mistake_type: Conceptual / Careless / Misread / Unknown
description: What went wrong?
correct_answer: What should have happened?
root_cause: Why did this happen?
fix_strategy: What will you do to prevent it next time?
confidence_level: 1-5
```
## 📌Example:
```
date: 2026-03-12
subject: Mathematics
topic: Integration by parts
mistake_type: Conceptual
description: Applied formula incorrectly and swapped terms
correct_answer: ∫u dv = uv - ∫v du
root_cause: Weak understanding of variable selection
fix_strategy: Practice 10 targeted problems + review theory
confidence_level: 2
```
